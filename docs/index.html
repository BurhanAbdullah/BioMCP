The platform

One installation. Multiple scientific capabilities.

BioMCP separates interoperability from scientific implementation. Servers remain independently executable, testable, and replaceable while the platform provides discovery, configuration, diagnostics, and transport.

Discover

Use a machine-readable registry to distinguish installable, validated, experimental, planned, and externally provided integrations.

Install

Use one CLI to select servers and configure supported AI clients without manually assembling every integration.

Compose

Allow agents to move between specialist scientific tools without merging or duplicating their scientific implementations.

Scientific boundary

Interoperability without replacing scientific authority.

Scientific software owns

Scientific computation, measurements, validation, evaluation, artifacts, and provenance remain with the underlying domain implementation.

→

BioMCP owns

MCP schemas, agent and client connectivity, server configuration, discovery, registry metadata, and transport.

Principle: AI predicts or requests; deterministic scientific software measures and validates. BioMCP is the interoperability bridge, not the scientific source of truth.
Quick start

Get started in minutes.

Install the package, inspect the registry, configure the servers you need, and run diagnostics before connecting an AI host.

pip install biomcp

biomcp list
biomcp install --servers bioimage --clients generic
biomcp doctor
Current ecosystem

Independent server families.

BioImage

Local image inspection, intensity summaries, and thresholding primitives.

ImageJ / Fiji

Interoperability with an explicitly configured local ImageJ/Fiji installation.

LLM

OpenAI-compatible model connectivity for scientific agent workflows using environment-provided credentials.

BioNuclei

Validated external scientific MCP interoperability. BioMCP can expose supported BioNuclei operations without duplicating its scientific engine.

Coming integrations: CellProfiler and additional scientific adapters are promoted only when an executable, tested integration and documented validation state exist.
