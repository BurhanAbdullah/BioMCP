Examples

From a scientific question to a tool call.

Explore the same interoperability boundary from several practical perspectives. The examples describe the workflow without hiding which component performs the scientific work.

Workflow 01

Inspect and quantify an image

A host can request image analysis and route the request to the appropriate scientific server.

User: Analyze this fluorescence image and count nuclei.\n\nAgent: Select an available BioMCP capability.\n\nServer: inspect_image\nServer: predict_image\nServer: load_result_summary
Workflow 02

Keep the result traceable

When the underlying server provides them, structured results can carry measurements, output artifacts, and provenance.

tool result\nsummary\nmeasurements\noutput files\nprovenance
Workflow 03

Keep orchestration separate from measurement

The agent interprets the request and selects a capability. The scientific server performs the computation and returns its result.

Agent: select capability and arguments\nBioMCP: connect and authorize\nScientific server: execute\nResult: structured scientific output
Agent

Request and orchestrate

Interpret the user's request, select an available capability, and provide the tool arguments.

Scientific server

Execute and validate

Perform the domain computation and return the authoritative scientific result.

Evidence boundary. BioMCP does not manufacture evaluation metrics for arbitrary user data. Scientific benchmark claims remain tied to defined protocols and evidence.
