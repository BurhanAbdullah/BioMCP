Contributing

Build the scientific MCP layer.

BioMCP grows through small, testable integrations. A new server should be useful to an AI host and explicit enough for a scientist to inspect and validate.

01 · Runtime

Provide a real server

Define executable MCP behavior with explicit tools, inputs, outputs, and transport.

02 · Registry

Describe the boundary

Add category, status, installability, command, transport, and scientific scope to the registry.

03 · Evidence

Test before promotion

Add regression tests, installation and usage documentation, and reproducible validation evidence.

Lifecycle

Promotion path

planned → experimental → validated → deprecated
Validation

What “validated” should mean

A server starting successfully is not enough. Validation should cover the tool contract, representative outputs, failure behavior, and the provenance boundary.

Keep changes reviewable. Prefer one coherent change per pull request, deterministic tests, explicit evidence, and documentation that matches the executable implementation.
