Architecture

A thin, explicit interoperability layer.

BioMCP separates discovery and client configuration from scientific execution. The host speaks MCP; the registered scientific server owns the computation.

Request path
01
AI hostNatural-language request and MCP client session.
02
BioMCP registry / runtimeDiscovery, configuration, authorization boundaries, and transport.
03
Scientific MCP serverDomain-specific tools and execution.
04
Result boundaryStructured output and provenance where provided by the scientific implementation.
Registry

Machine-readable truth

Server metadata describes capabilities, transport, lifecycle state, and installability.

Runtime

Controlled launch

Registry-backed commands and client configuration keep integration paths explicit rather than implicit.

Science boundary

Authority stays local

Routing metadata is not treated as scientific evidence. The underlying domain software remains authoritative.

Lifecycle

Promotion requires evidence.

StageMeaning
PlannedCatalogued but not installable.
ExperimentalRunnable integration under active validation.
ValidatedExecutable integration with tests and documented evidence.
DeprecatedRetained for compatibility or history, but no longer an active integration path.
Core principle: AI can request and orchestrate. Deterministic scientific software performs and validates domain computation.
