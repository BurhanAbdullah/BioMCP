Architecture

A thin interoperability layer.

BioMCP keeps discovery and client configuration separate from scientific execution. A host speaks to MCP; the registered scientific server owns the actual computation.

Registry

Machine-readable server metadata, capabilities, transport, status, and installability.

Runtime

Registry-backed launch commands and client configuration. No hidden server substitution.

Science boundary

BioMCP never turns routing metadata into scientific claims. Underlying software remains authoritative.
